# CI mínimo + fix e2e Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Separar los runners de test (Vitest para unit, Playwright para e2e) para que `npm test` deje de fallar en `tests/e2e/scan-cycle.spec.js`, y agregar un workflow de GitHub Actions que corra ambas suites en cada push/PR a `develop`/`master`.

**Architecture:** Vitest ignora explícitamente `tests/e2e/**`. Playwright gana un `webServer` que levanta `tests/e2e/server.mjs` automáticamente contra el puerto que ya usa `baseURL`. Un job único de GitHub Actions corre `npm test` y luego `npm run test:e2e`.

**Tech Stack:** Vitest 4, Playwright 1.61, GitHub Actions, Node 20.

## Global Constraints

- No se toca el deploy de Vercel — sigue auto-deployando en push, sin cambios.
- No se agrega build ni typecheck al CI: no hay TypeScript ni bundler propio en este repo.
- El puerto del servidor e2e es `3456` (existente en `tests/e2e/server.mjs` como default via `process.argv[2]`).

### Task 2: Auto-levantar el servidor e2e en Playwright y agregar script `test:e2e`

**Files:**
- Modify: `playwright.config.js`
- Modify: `package.json:9-10`
- Test: manual (correr `npm run test:e2e`)

**Interfaces:**
- Consumes: `tests/e2e/server.mjs` (ya existe, acepta el puerto como `process.argv[2]`, sirve estático desde la raíz del repo).
- Produces: script npm `test:e2e` — Task 3 lo invoca desde CI.

- [ ] **Step 1: Reemplazar `playwright.config.js` completo**

```js
const { defineConfig } = require('@playwright/test');

module.exports = defineConfig({
  testDir: './tests/e2e',
  timeout: 30000,
  webServer: {
    command: 'node tests/e2e/server.mjs 3456',
    url: 'http://localhost:3456',
    reuseExistingServer: !process.env.CI,
    timeout: 10000,
  },
  use: {
    baseURL: 'http://localhost:3456',
    viewport: { width: 390, height: 844 },
    ignoreHTTPSErrors: true,
  },
});
```

- [ ] **Step 2: Agregar script `test:e2e` en `package.json`**

En el bloque `"scripts"`, agregar después de `"test:watch": "vitest"`:

```json

```

(recordar la coma después de `"test:watch": "vitest"`)

- [ ] **Step 3: Instalar el browser de Playwright si falta**

- [ ] **Step 4: Correr la suite e2e**

### Task 3: Workflow de GitHub Actions

**Files:**
- Create: `.github/workflows/ci.yml`
- Test: push a una rama de prueba o abrir un PR, confirmar que el check corre en GitHub

**Interfaces:**
- Consumes: `npm test` (Task 1) y `npm run test:e2e` (Task 2).
- Produces: check de GitHub Actions llamado `test` en el job `CI` — sirve como base para marcarlo "required" en la protección de rama (paso manual, fuera de este plan).

- [ ] **Step 1: Crear `.github/workflows/ci.yml`**

```yaml
name: CI

on:
  push:
    branches: [develop, master]
  pull_request:
    branches: [develop, master]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Run unit tests
        run: npm test

      - name: Install Playwright browsers
        run: npx playwright install --with-deps chromium

      - name: Run e2e tests
        run: npm run test:e2e
```

- [ ] **Step 2: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add GitHub Actions workflow for unit and e2e tests"
```

- [ ] **Step 3: Push y verificar en GitHub**

Run: `git push origin develop` (o la rama de trabajo, luego abrir PR)
Expected: en la pestaña "Actions" del repo en GitHub aparece el workflow "CI" corriendo, y termina en verde (✓) tras `npm test` y `npm run test:e2e`.

- [ ] **Step 4: Acción manual pendiente (no automatizable desde este plan)**

En GitHub: Settings → Branches → Branch protection rules → agregar/editar regla para `develop` y `master` → marcar el check `test` como "required" antes de mergear. Esto es lo que convierte el CI en un gate real, no solo informativo.
